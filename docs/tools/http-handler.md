# HTTP Handler Pattern

This page describes how to implement HTTP handlers in a waffle service using `gitlab.com/gorib/http/server`.

## Handler signature

Every route handler has the same signature:

```go
func(c *fiber.Ctx) (server.Response, error)
```

Wrap it with `server.Handler` before passing to fiber:

```go
func (r *Router) Setup(app *fiber.App) {
    v1 := app.Group("/v1")
    v1.Get("/users/:id", server.Handler(r.handler.Get))
    v1.Post("/users", server.Handler(r.handler.Create))
}
```

`server.Handler` handles the translation between the `(Response, error)` return and fiber's `error`-only convention. It sets the status code and content-type header from the returned `Response`.

## Parsing and validating requests

Each service has a local `pkg/validator` package with a `Parse` function:

```go
// pkg/validator/parse.go
package validator

import (
    "encoding/json"
    "github.com/mailru/easyjson"
)

type Validatable interface {
    Validate() error
}

func Parse[T any](b []byte) (*T, error) {
    r := new(T)
    if e, ok := any(r).(easyjson.Unmarshaler); ok {
        err = easyjson.Unmarshal(b, e)
    } else {
        err = json.Unmarshal(b, r)
    }
    if err != nil {
        return nil, err
    }
    if v, ok := any(r).(Validatable); ok {
        if err = v.Validate(); err != nil {
            return nil, err
        }
    }
    return r, nil
}
```

`Parse` automatically calls `Validate()` if the type has one — generated by `whisk`. Use it at the top of every handler that accepts a request body:

```go
req, err := validator.Parse[createRequest](c.Body())
if err != nil {
    return nil, err
}
```

## Response helpers

```go
import (
    "github.com/valyala/fasthttp"
    "gitlab.com/gorib/http/server"
)

// JSON response (most common)
return server.NewJsonResponse(fasthttp.StatusOK, &userResponse{Id: user.Id})

// Plain text
return server.NewResponse(fasthttp.StatusOK, lo.ToPtr("ok"))
```

Both functions accept a pointer to the payload. For JSON, the payload is marshalled automatically.

## Local DTOs

Request and response structs with `json` tags live in the `cmd/http` layer — never in `model/`. They are local to the transport:

```go
//go:generate go tool whisk -validate.storage=pkg/validator $GOFILE

package http

type createRequest struct {
    Email string `json:"email" validate:"required,email"`
    Name  string `json:"name"  validate:"required,min=2"`
}

type userResponse struct {
    Id    int    `json:"id"`
    Email string `json:"email"`
    Name  string `json:"name"`
}
```

The `//go:generate` directive triggers `whisk` to generate a `Validate()` method on request structs.

## Full handler example

```go
package http

import (
    "github.com/gofiber/fiber/v2"
    "github.com/valyala/fasthttp"
    "gitlab.com/gorib/http/server"
    "mymodule/domain/user/model"
    "mymodule/pkg/validator"
)

type UserManagement interface {
    GetUser(ctx context.Context, id int) (*model.User, error)
    CreateUser(ctx context.Context, email, name string) (*model.User, error)
}

type userHandler struct {
    management UserManagement
}

func NewUserHandler(management UserManagement) *userHandler {
    return &userHandler{management: management}
}

func (h *userHandler) Get(c *fiber.Ctx) (server.Response, error) {
    id, err := c.ParamsInt("id")
    if err != nil {
        return nil, err
    }

    user, err := h.management.GetUser(c.Context(), id)
    if err != nil {
        return nil, err
    }

    return server.NewJsonResponse(fasthttp.StatusOK, &userResponse{
        Id:    user.Id,
        Email: user.Email,
        Name:  user.Name,
    })
}

func (h *userHandler) Create(c *fiber.Ctx) (server.Response, error) {
    req, err := validator.Parse[createRequest](c.Body())
    if err != nil {
        return nil, err
    }

    user, err := h.management.CreateUser(c.Context(), req.Email, req.Name)
    if err != nil {
        return nil, err
    }

    return server.NewJsonResponse(fasthttp.StatusCreated, &userResponse{
        Id:    user.Id,
        Email: user.Email,
        Name:  user.Name,
    })
}
```

## Wiring in DI

The handler and router are both concrete types — use `di.Define`:

```go
di.Define(http.NewUserHandler)
di.Define(api.NewRouter)
```

The service dependency (`UserManagement`) is resolved automatically from the registered aliases. If the service struct satisfies multiple interfaces, declare them with `di.Alias` when registering the service:

```go
di.Define(service.NewUserService,
    di.Alias[httpCmd.UserManagement](),
    di.Alias[grpcCmd.UserManagement](),
)
```

## Guidelines

- **Never use `c.BodyParser`** — always use `validator.Parse`.
- **No logging in handlers** — errors propagate to the framework, which logs them. Log only when you need extra context specific to this handler.
- **No `json` tags in `model/`** — DTOs with json tags belong in `cmd/http`.
- **Context from fiber**: pass `c.Context()` to all service calls — it carries the session populated by the session middleware.
