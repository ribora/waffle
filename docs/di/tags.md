# DI Tags

[Docs](../README.md) · Dependency injection

Tags are empty struct values used to group multiple values of the same interface into a collected slice. Each waffle tool defines its own tags. You register your implementations under those tags; the tool's `InitXxx` registrations collect them using `di.Tags[Interface](tag)`.

**A tagged registration is a collection member and nothing else.** It never competes for a slot, and it cannot satisfy a plain constructor argument either: a parameter of type `server.Interceptor` will not be filled with one of the interceptors you tagged, because picking one of several would be an arbitrary choice. Diogen refuses to generate instead:

```
dependency for mw (server.Interceptor) in *pkg.Thing is provided only by tagged
registrations (pkg.NewTracing, pkg.NewLogging): a di.Tag registration is a
collection member — collect them with di.Tags, or drop the tag to wire it directly
```

If you need the same implementation both in a collection and as a direct dependency, take `[]I` and pick from it. Registering the same constructor twice does not work: both registrations would be built and would claim the same container field, and Diogen refuses to generate (`is registered twice and both registrations are built`).

A tagged registration has no `Replacements` entry of its own, since replacing one member cannot change the membership of the collection — but the collection itself does: `di.Tags[Interface](tag)`'s consumer gets a `Replacements` field of type `[]Interface` that replaces the whole collection at once. A member's own constructor is skipped only if it feeds nothing but that one collection; one feeding more than one collection (two tags on one registration, or one tag gathered under two different interfaces) always builds for real regardless of what you supply. See [Testing with the container](overview.md#testing-with-the-container).

## app.CommandTag

**Package:** `gitlab.com/gorib/waffle/app`

Collects every `app.Command` in the container. The app uses this slice to populate the command registry.

```go
di.Define(sweepotp.NewSweepOtpCommand, di.Tag(app.CommandTag))
```

`di.Define`, because a command is looked up in the registry by name and is never
a dependency of anything else — nothing here wants an interface. That is what
`waffle make:domain:command` writes.

The tool commands are the one exception, and for a reason that does not
generalise: each wires a marker interface of its own —
`di.Wire[http.HttpCommand](http.NewHttpCommand, di.Tag(app.CommandTag), …)` — so
that `di.For[http.HttpCommand]()` can give that command its own `app.BaseCommand`
without every other command in the container claiming the same slot. A service
with one name and one description per command needs none of it.

See [core/commands](../core/commands.md#registering-a-custom-command).

## grpc.ServiceTag

**Package:** `gitlab.com/gorib/waffle/tools/grpc`

Collects `ServiceHandler` implementations — one per gRPC service. Generated by `waffle make:domain:grpc`.

Use `di.Define` (not `di.Wire[ServiceHandler]`) — handlers are concrete types, not interface bindings:

```go
di.Define(usergrpc.NewUserGrpc, di.Tag(grpcCommand.ServiceTag))
di.Define(paymentgrpc.NewPaymentGrpc, di.Tag(grpcCommand.ServiceTag))
```

On startup, `GrpcCommand` calls `Start(registrar)` on each collected handler.

## grpc.MiddlewareTag

**Package:** `gitlab.com/gorib/waffle/tools/grpc`

Collects unary server interceptors (built-in tracing/status/session/log/recover plus user-defined). Chained by `Order()` ascending (smaller = outer).

```go
di.Define(NewAuthInterceptor, di.Tag(grpcCommand.MiddlewareTag))
di.Define(NewAuditInterceptor, di.Tag(grpcCommand.MiddlewareTag))
```

---

## grpc.StreamMiddlewareTag

**Package:** `gitlab.com/gorib/waffle/tools/grpc`

Same as `MiddlewareTag` but for stream interceptors.

```go
di.Define(NewStreamAuditInterceptor, di.Tag(grpcCommand.StreamMiddlewareTag))
```

## grpc.ErrorMapperTag

**Package:** `gitlab.com/gorib/waffle/tools/grpc`

Collects `server.ErrorMapper` implementations — domain error → gRPC code maps. The framework merges them into a single `ErrorMapper` consumed by the built-in `status` and `log` interceptors (one map for both unary and stream chains).

```go
di.Define(domainErrors.NewMapper, di.Tag(grpcCommand.ErrorMapperTag))
```

## http.RouterTag

**Package:** `gitlab.com/gorib/waffle/tools/http`

Collects `server.Router` implementations — one per domain that serves HTTP. Generated by `waffle make:domain:http`.

```go
di.Define(userHttp.NewRouter, di.Tag(httpCommand.RouterTag))
di.Define(billingHttp.NewRouter, di.Tag(httpCommand.RouterTag))
```

On startup the `http` command hands the collection to `http.Setup`, which puts the global chain on the mux once and then calls each router's `Setup` with a group of its own — so the routes share one mux while a `Use` stays with the router that added it. Two routers claiming the same method and path is an error that names both, and an empty collection is an error too — see [tools/http](../tools/http.md#one-server-every-domains-routes).

There is no untagged form: `di.Wire[server.Router](...)` fills a slot nothing asks for any more, so a router registered that way reaches no server at all.

## scribus.MiddlewareTag

**Package:** `gitlab.com/gorib/waffle/tools/scribus`

Collects `scribus.Middleware` interceptors — each wraps `func([]scan.Source) error` — applied around the consumer's dispatch handler in `Order()` sequence.

```go
di.Define(interceptor.NewTracing, di.Tag(scribus.MiddlewareTag))
di.Define(interceptor.NewLog, di.Tag(scribus.MiddlewareTag))
di.Define(interceptor.NewRecover, di.Tag(scribus.MiddlewareTag))
```

(HTTP middleware is not tag-collected — the chain around every request is one `http.Global`, and anything narrower is a `server.Layer` on a route, a group, or the router's own `mux`.)

## migrate.MigrationsTag

**Package:** `gitlab.com/gorib/waffle/tools/migrate`

Collects migration sources — one per domain that has migrations. Generated by `waffle make:domain:migrate`.

Each domain's migrate package exports `NewMigrations()` returning the embedded SQL files:

```go
// domain/user/cmd/migrate/main.go
package migrate

import (
    "embed"
    "io/fs"
)

type Migration interface {
    fs.FS
}

//go:embed migrations/*
var migrations embed.FS

func NewMigrations() embed.FS {
    return migrations
}
```

Register with `di.Wire` under that domain's own `Migration`, which is what
`waffle make:domain:migrate` writes:

```go
import userMigration "mymodule/domain/user/cmd/migrate"

di.Wire[userMigration.Migration](userMigration.NewMigrations, di.Tag(migrate.MigrationsTag))
```

The one-line interface per domain is the point: a container field is named
after the type it is exposed as, so `di.Define` on `embed.FS` would give every
domain's migrations the same name. All collected sources are applied in
sequence when the `migrate` command runs.

## scribus.CommandTag

**Package:** `gitlab.com/gorib/waffle/tools/scribus`

Collects `Handler` implementations for the single-mode consumer. Each handler declares its subjects via `Keys()`.

```go
di.Wire[scribus.Handler](NewOrderCreatedHandler, di.Tag(scribus.CommandTag))
di.Wire[scribus.Handler](NewOrderCancelledHandler, di.Tag(scribus.CommandTag))
```

On startup the scribus command builds a routing table from all registered handlers and dispatches by subject.

For batch mode, register a `BatchHandler` without a tag:

```go
di.Wire[scribus.BatchHandler](scribusCommand.NewNotificationAcceptedCommand)
```
